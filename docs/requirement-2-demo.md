# المتطلب الثاني: خطوات العرض في المقابلة

كل الأوامر تُنفّذ من مجلد المشروع، والمشروع يعمل (`docker compose up -d`).

## البنية باختصار

```
المتصفح ← nginx ← Laravel (PHP) ──gRPC──► خدمة المستودع (Node.js) ← قاعدة بيانات المستودع
                       │
                       └──► قاعدة بيانات التطبيق
```

- العقد المشترك: `proto/inventory/v1/inventory.proto`
- خدمة المستودع: `inventory-service/` (لغة مختلفة عن التطبيق، وقاعدة بيانات خاصة بها `inventory-db`)
- التطبيق لا يقرأ قاعدة بيانات المستودع أبداً، يتكلم مع الخدمة فقط عبر العقد.

## 1) عدة طلبات في نفس اللحظة على آخر قطعة (Race Condition)

```bash
docker compose exec app php artisan demo:race --buyers=10
```

النتيجة المتوقعة: طلب واحد فقط يُنشأ (201)، والتسعة الباقون يُرفضون (422) برسالة
"الكمية المتوفرة ... هي 0 فقط"، والمخزون يصبح 0 ولا ينزل تحته.

**لماذا ينجح طلب واحد فقط؟** خدمة المستودع تحجز داخل transaction وتقفل سطر المنتج
(`SELECT ... FOR UPDATE`)، فالطلبات المتزامنة تُخدم واحداً بعد الآخر: الأول يأخذ القطعة،
والباقون يجدون الكمية 0. (الكود: `inventory-service/src/inventory.js` → `reserve`)

اختبار نفس الحالة على مستوى الخدمة (20 طلباً متزامناً):

```bash
docker compose run --rm inventory npm test
```

## 2) ماذا يرى المستخدم عندما تتوقف خدمة المستودع

```bash
docker compose stop inventory
```

- صفحة المنتجات تبقى تعمل، والكمية تظهر "الكمية غير معروفة حالياً".
- عند تأكيد الطلب من السلة تظهر رسالة واضحة: "خدمة المستودع لا تستجيب حالياً..."
  (رد 503)، ولا يُنشأ أي طلب، والسلة تبقى كما هي.
- المستخدم لا ينتظر بلا نهاية: لكل نداء gRPC مهلة 2 ثانية (`INVENTORY_TIMEOUT_MS`).

ثم نعيد تشغيلها:

```bash
docker compose start inventory
```

## 3) خدمة المستودع بطيئة

```bash
SIMULATE_DELAY_MS=5000 docker compose up -d inventory
```

الخدمة تتأخر 5 ثوانٍ في كل رد، لكن التطبيق يتوقف عن الانتظار بعد ثانيتين ويعطي نفس الرسالة
الواضحة. للعودة للوضع الطبيعي:

```bash
docker compose up -d inventory
```

## 4) فشل حفظ الطلب بعد الحجز (التعويض)

إذا نجح الحجز في المستودع ثم فشل حفظ الطلب في قاعدة بيانات التطبيق، يُرسل التطبيق
`Release` فترجع الكمية المحجوزة. الكود: `backend/app/Modules/Orders/Services/OrderService.php`
(الدالة `compensate`)، والاختبار:

```bash
docker compose exec app php artisan test --filter=InventoryFailureTest
```

## العمليات في العقد

| العملية | متى تُستخدم |
|---|---|
| `GetStock` | عرض المنتجات وتفاصيل المنتج (كم بقي؟) |
| `Reserve` | إنشاء الطلب: طلب واحد يحجز كميات كل منتجات الطلب، الكل أو لا شيء |
| `Release` | إرجاع ما حُجز إذا فشل الطلب أو أُلغي (آمن لو استُدعي مرتين) |
| `SetStock` | إضافة إضافية: تحديد مخزون منتج جديد يضيفه المسؤول |
